# Munin Assistant for Google Docs

Chrome extension (Manifest V3) that adds an AI assistant panel to Google Docs. The assistant reads the document with tools and edits it: by replacing the selection, or through the Google Docs API with verified, undoable edits. Providers: Munin, OpenAI, Anthropic, with your own API key. No server of its own, no telemetry.

## Install

1. Download the repository (Code → Download ZIP) and unpack it, or clone it.
2. `chrome://extensions` → Developer mode → Load unpacked → the folder with `manifest.json`. Chrome 116 or newer.
3. Open a Google Docs document (reload a tab that was already open) and click the extension icon.

## Setup

- Gear icon → Add provider → choose the type in the new row (Munin, OpenAI, Anthropic or Custom; several accounts of one kind are fine, each with its own name) → paste the API key. A Munin account can use its own server URL. Custom connects any OpenAI-compatible server (vLLM, llama.cpp, LM Studio, Ollama, OpenRouter …): enter its URL, and a key only if it needs one. When Chrome blocks a server that does not allow requests from the extension (CORS), the row says so and **Check provider** asks Chrome for access to that server. Servers such as Yandex AI Studio need extra headers: add them under **Extra headers**, one per row with **Add header** (name `OpenAI-Project`, value your folder ID). **Advanced** in a provider row sets the reply length and temperature per provider (for all its models); you can also ask the assistant to change them. Every change applies at once; a click outside closes the settings. Keys: Munin Chat → Settings → API Keys; [platform.openai.com](https://platform.openai.com/); [console.anthropic.com](https://console.anthropic.com/).
- Optional: Settings → Google account → Sign in with Google. Enables precise edits anywhere in the document through the Docs API, with verification and Undo, plus formatting, tables, headers, footers, footnotes, sections (columns, a landscape page in the middle, section margins) and comments. If the consent window says the app is not verified: Advanced → Go to … → Allow.
- References: citations from a local Zotero 7 library or by DOI. The assistant asks in the chat before it looks up references through Zotero, Crossref or OpenAlex; Allow once, and remove the access in chrome://extensions if you change your mind.

| Provider | API | Notes |
|---|---|---|
| Munin | OpenAI-compatible Chat Completions, `api.muninai.org` (or your own Munin server URL) | Also the `/code` command and Munin's paper search |
| OpenAI | Responses API | Web search in answers |
| Anthropic | Messages API | Web search in answers |
| Custom | Any OpenAI-compatible server: `POST /chat/completions`, `GET /models` (vLLM, llama.cpp, LM Studio, Ollama, OpenRouter …) | Your server URL, a key only if the server needs one; the model list, context window and reply size come from the server's `/models` answer (otherwise 32k context, 4k reply); if the server does not allow requests from the extension (CORS), **Check provider** asks Chrome for access to it; extra request headers (Yandex AI Studio: `OpenAI-Project` with your folder ID) go into **Extra headers**, one per row with **Add header** |

The model is chosen per chat in the model menu under the input (see Use); the menu lists the models each account reports.

## Use

- The model name under the input opens the model menu: pick the provider and model for this chat. A new chat starts with the model of the chat you were in. A green dot marks a provider that answered with its model list, a red one a provider that did not answer or refused a chat request, a grey one a provider not checked yet; **Check provider** asks it again and sends a one-token test message to make sure the chat works.
- Select text, type a request, press Enter. A click on the mode button under the input opens a menu with **Manual** (the default: the assistant asks before each edit and shows you the new text), **Auto** (the assistant edits the document without asking) and **Plan** (a numbered plan of edits first; **Do it** carries it out). The **/** button next to it lists the commands. Shift+Enter adds a line; Enter during an answer queues the next message.
- On OpenAI and Anthropic accounts the assistant can search the web in any answer when it needs current facts or sources (the provider bills the searches).
- With a Munin API key in the settings, the assistant (on any provider) can also search Munin's lab database of papers or the web through Munin; the searches count against the key's monthly quota.
- Edits through the Docs API are verified by re-reading the document and get an Undo arrow (↶) at the end of their row; the Undo all arrow (⟲) beside it reverts an answer's edits together. In Auto only an edit that mentions a person asks first (Docs may notify them). The assistant sees smart chips, dates, dropdowns and image alt text, and can insert person, date and Drive, YouTube or Calendar link chips. A long text is written section by section from an agreed outline with a checklist in the chat; a whole section can be revised paragraph by paragraph, and a passage can be trimmed to a word count ("cut the abstract to 250 words": the panel counts the words, not the model).
- Agents: for a sizeable side task the assistant can start an agent that works in the background while you go on in the chat; its report arrives in the chat and the assistant answers with it. The **N agents** button next to the mode button opens the agent map: every agent of the document with its status, model, time and tokens, its prompt, tool calls and report, and **Stop** for a running one (an agent running when the panel is reloaded is lost).
- Slash commands: `/research` (a sourced research report with "Ask about" follow-ups), `/code` (Munin only), `/chat`, `/review` (an independent review: findings that quote the document, with line links and Fix flagged), `/side` (a side question that is not saved), `/check` (a pre-submission report; ask for a CONSORT, PRISMA, STROBE, ARRIVE, CARE or TRIPOD+AI check to get a coverage table), `/polish` (prose fixes for the selection, a section named after it or a short document, each with **Apply**: mechanical swaps and the model's sentence fixes, without the ones that would change a number, a citation or the strength of a claim), `/test` (self-test on an empty document).
- Files: the folder button in the header lists `MAIN.md` (your instructions for every document), `DOC.md` (this document's instructions) and the document's attached files. Both instruction files are sent with every message; "From now on…" / "remember…" adds a rule, "learn my style" saves a style profile. On your first message in a document the assistant reads it and writes `DOC.md` for you (language, terms, citation style, what you want); edit it any time in Files.
- Formatting: new and restyled paragraphs get Times New Roman (body 12 pt, justified, no space between paragraphs; headings 16, 14 and 12 pt with space above only; the weight stays as the document has it) unless a `Formatting:` line in `DOC.md` or `MAIN.md` says otherwise, for example `Formatting: body Arial 11 left space 0/6; h1 18 bold center`; a document that already uses other fonts, alignment or spacing gets that line written for it on the first message. Numbered headings get no indent: the number sits at the margin with the heading text right after it, in line with the body text; `numbers 0.6/0.9/1.2` in that line moves the heading text to those positions (cm, by level) and `numbers docs` keeps Google Docs' own list indents. The document's styles (Normal text, Heading 1–6) are set to the sheet only when you ask (the assistant may offer it when they differ), so text you type later matches it (Undo restores them). Ask "apply the formatting to the whole document" to bring existing paragraphs in line. The same line can set the page (`page A4 landscape, margins 2.5 cm, first page number 3`) and start each chapter on a new page (`h1 page-break`); the page setup changes only when you ask, and Undo restores it.
- Tables (with the Google account): ask to insert a table, add or delete rows and columns, set column widths, repeat header rows on every page, shade cells, change the borders (all lines, publication-style horizontal rules, a frame, none) or merge and unmerge cells; Undo restores each change, except that undoing a merge leaves the joined text in the first cell.
- Comments (with the Google account): the assistant reads the comment threads and suggested changes, and adds comments, replies, resolves or reopens threads and accepts or rejects suggested changes when you ask. Deleting a comment always asks first unless your message says to delete it; accepting or rejecting more than five suggestions asks too. Undo removes an added comment or reply and reopens a resolved thread; accepted or rejected suggestions are undone with Ctrl+Z in Google Docs.
- Suggested edits (experimental, with the Google account): a line `Edits: suggest` in `DOC.md` makes the assistant write its text changes as suggestions, so your co-authors see them as tracked changes and accept or reject them in Google Docs (deleted text stays visible, struck through, until then). Formatting, tables, headers and footers are still changed directly. Undo withdraws the assistant's own suggestion; text inside a suggestion is not edited until someone accepts or rejects it. Remove the line (or write `Edits: direct`) to edit directly again.
- `/check` also lists leftovers (TODO, `[ref]`, highlighted placeholders, double spaces), mixed forms (UK and US spelling, hyphenation, numbers as numerals or words, p or P, % or percent, ± or +/-; with the Google account **Apply** unifies a group to its majority form in one edit you can undo), abstract and limitations issues, a density line per section, and, when you attach the journal's author guidelines, their limits (the chat's model reads the limits once). A line `Checks: ignore <rule-id>; accept <term>` in `DOC.md` silences a rule (its id is in the finding's fold) or a term.
- Attachments: the **+** button (or a drop on the chat, files pasted into the input, or **Add file** in Files) attaches text, Markdown, .docx and .pdf files to the document, so every chat of it can read them; Files shows the text the assistant reads and removes a file. The assistant never changes them; they are read in the browser, and only the parts the assistant reads go to the provider.
- Up to 30 chats per document, shared between the tabs of one document; long chats are condensed automatically. Light and dark themes.

## Privacy

Document text, selection and messages go only to the selected provider with your key. API keys, chats and settings are stored locally in the browser. Once a day the panel also asks GitHub for the latest version number; that request carries none of your data. Policy: https://iyushin.ru/munin/privacy.html

## Update

About once a day the panel asks GitHub whether a newer version exists (one request for this repository's `manifest.json`; nothing about you or your documents is sent). A newer version shows as a dot on the gear icon and at the bottom of Settings.

Pull or download the new version, click the reload icon on the extension card in `chrome://extensions`, reload the Docs tabs. Keys saved by an earlier version become providers in the new list by themselves; existing chats keep the provider and model you used last. Files attached in a chat by an earlier version move to the document's Files by themselves.
